# Geographic data

Files the API reads that are too large for `data/reference/`, which the iPhone app bundles whole (ADR-041 §4).

| File | Source | How it stays correct |
|------|--------|----------------------|
| `circonscriptions.geojson` | "Contours géographiques des circonscriptions législatives" on data.gouv.fr (p20 variant, 2024-06-13, Licence Ouverte 2.0), recorded in `api/circonscriptions_data.py` | Generated by `scripts/export_circonscriptions.py`; `tests/unit/test_circonscription_boundaries.py` fails on a missing, extra, invalid or overlapping seat |

## circonscriptions.geojson

The boundaries `POST /circonscriptions/locate` matches a point against (ADR-047).
One feature per seat, with only `department` and `circonscription` (keyed like `deputies`) and the geometry.
The file's top-level `source` names the dataset, its producer, version and licence.

It covers 559 of the 577 seats.
The 11 seats abroad and the overseas collectivités the source does not draw (Saint-Barthélemy et Saint-Martin, Wallis-et-Futuna, Polynésie française, Nouvelle-Calédonie) are listed in `SEATS_WITHOUT_SHAPE`.

The source is not official and is simplified.
`scripts/measure_circonscription_accuracy.py` checks it against Base Adresse Nationale addresses in communes that lie wholly inside one seat, and its results set the boundary tolerance (ADR-047 §5, #661).
It also checks communes split between seats against Insee's extract of the electoral register, where each address has the seat of its polling station (#670).
At the 50 m tolerance, one wrong seat is 0.010 % of addresses in Paris, Marseille and Lyon and 0.065 % in the other split communes, against 0.001 % in communes wholly inside one seat measured the same way; ADR-047 records the full figures and #671 the open question.

Regenerate only when the source publishes a new version or a redistricting happens:

```sh
python scripts/export_circonscriptions.py
```

Then update `BOUNDARY_SOURCE` and rerun the measurement before committing.
