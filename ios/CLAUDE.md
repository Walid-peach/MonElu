# ios/CLAUDE.md

Rules for agents working on the MonÉlu iPhone app.
The root [`CLAUDE.md`](../CLAUDE.md) and [`docs/decisions.md`](../docs/decisions.md) still apply; this file adds what is specific to `ios/`.
ADR-041 is the decision this app is built on - read it before changing anything here.

## What this app is

A SwiftUI client (Swift 6, strict concurrency, iOS 17 minimum) for the public MonÉlu API.
Android users stay on the website and its PWA (ADR-041 §2).
The work is tracked under epic #429, one phase epic at a time.

## Rules

1. **The API computes, the app shows** (ADR-041 §4).
   Scorecards, presence rates, quiz matching, RAG answers, verdicts and share URLs all come from the API.
   Never reimplement one in Swift, not even "just for display".
   If a screen needs a number the API does not return, the change belongs in `api/` first.
2. **Never edit generated files.**
   `MonElu.xcworkspace`, `MonElu.xcodeproj` and `Derived/` are generated by Tuist from `Project.swift` and are git-ignored.
   Change the project structure in `Project.swift`, then run `make ios-generate`.
   The generated API client (#448) is the same: regenerate it, never patch it.
3. **Shared tables have one source.**
   Departments, groups, themes and vote-position labels come from `data/reference/*.json` (exported from `api/*_data.py`).
   Bundle that JSON; never hand-copy a table into Swift.
4. **Caveats and the data horizon come from `GET /app/config`**, so their wording changes without an app release.
   Never hard-code a caveat text in the app.
5. **The API contract is additive only** (ADR-041 §5).
   If an app change needs a different API shape, add a field or route; never rename, retype or remove one the app reads.
   operationIds are handler names in camelCase, so renaming a handler is an API change.
6. **No Railway hostname in a public App Store build.**
   TestFlight builds may use it; the public release waits for the API subdomain (#419, #433).
7. **Reading never requires an account** (ADR-040 §6).
   When accounts reach the app (#434), the session lives in the Keychain and FastAPI gets the bearer token (ADR-041 §6); nothing else changes for anonymous reading.
8. **No push, no analytics SDK.**
   Push is out of v1 (ADR-041 §7, #359); errors go to Sentry only.
9. **Every PR proves itself** (ADR-041 §8).
   `make ios-test` must pass, and a PR that changes a screen carries screenshots in light and dark mode.

## Layout

| Path | What it is |
|------|------------|
| `Project.swift`, `Tuist.swift` | Tuist manifests; the only place the project structure is defined |
| `mise.toml` | Pins the Tuist version; `scripts/ios.sh` installs it through mise |
| `Configs/App.xcconfig` | Bundle id, version numbers. The bundle id is a placeholder until the publisher is decided (#451) |
| `MonElu/Sources` | The app target: app entry point and the root tab bar only |
| `MonElu/Tests` | Tests of the app target |
| `Packages/MonEluCore` | Plain Swift models and domain types, no UI and no networking |
| `Packages/MonEluAPI` | The API client (#448) |
| `Packages/MonEluUI` | Design tokens and shared SwiftUI components (#447) |
| `Packages/MonEluAccount` | Sign-in and account data (#434) |
| `scripts/ios.sh` | What the Makefile targets run |

Feature code goes in a package, not in the app target, so it can be tested on its own.
Every package has at least one Swift Testing test (`import Testing`, `@Test`, `#expect`); do not add XCTest.

## Build and test

Use the Makefile targets from the repository root.
They are the only build entry points: do not call `xcodebuild` or `tuist` directly.

```bash
make ios-generate   # generate the Xcode workspace from Project.swift
make ios-build      # build the app for the Simulator
make ios-test       # app tests + every package's tests on the Simulator
make ios-run        # build, install and launch in the Simulator
```

Requirements: Xcode 27 with an iOS Simulator runtime (`xcodebuild -downloadPlatform iOS`), and mise (`brew install mise`), which installs the pinned Tuist on first use.

`IOS_SIMULATOR_ID=<udid>` picks a Simulator; otherwise the first iPhone on the newest runtime is used.
Build products go to `~/Library/Caches/MonElu-ios/<checkout hash>/`, outside the repository: the checkout may live in an iCloud-synced folder, and codesign refuses a bundle carrying the extended attributes iCloud adds.
